1.1 ASSESSMENT SCOPE & METHODOLOGY
----------------------------------
This report synthesizes a 5-phase, report-only quality assurance, testing, and
senior code review of the Hello-Guys Django 5.1.15 backend across its six core
modules (`core`, `crm`, `pms`, `meta_connector`, `cms`, `hello_guy_ai`), shared
configuration (`config/`), global UI templates (`templates/`), and the unmounted
`voice_agent/` app:

  - Phase 1 (Baseline & Automated Tests): Executed `manage.py check`,
    `manage.py check --deploy`, all 7 target pytest suites, and full-repo
    test discovery without mutating `.venv`, `pyproject.toml`, or any test file.
  - Phase 2 (UI/UX & Frontend): Audited `templates/base.html`, Display popover,
    Floating AI Chat widget, Global Notification & Reminders bell, `/reminders/`
    14-day SVG chart, `g:i A` AM/PM formatting, CRM Meetings/Transcripts/Inbox,
    PMS `pmsTree` Alpine bulk builder, `/meta/` & `/meta/approvals/`, `/chat/`,
    `/ai/analytics/`, Dark/Light mode tokens, and mobile responsiveness.
  - Phase 3 (Backend, DB & Permissions): Audited `Viewer`/`Agent`/`Admin` RBAC
    scoping, `403`/`404` isolation, `pms.services.create_tree` atomicity &
    `RestrictedError`, N+1 queries, Google Calendar/Drive sync (`crm/google.py`),
    and the CMS -> CRM lead pipeline (`InquiryCreateAPIView` and
    `InquirySubmissionAdmin` removal verified).
  - Phase 4 (AI/LLM & Agentic): Audited `WebsiteAssistant` (`create_inquiry` &
    `create_global_reminder`), `core/ai_tools.py`, `LLMModel` provider prefix
    validation (`litellm.get_llm_provider`), RAG/Milvus isolation, Dramatiq &
    scheduler reliability, prompt injection hardening, and `/meta/approvals/` HITL.
  - Phase 5 (Security & Code Quality): Audited secrets & `FIELD_ENCRYPTION_KEY`,
    SQLi, XSS, CSRF, Open Redirects, Meta webhook signature verification, plus
    an AST sweep across 235 non-migration Python files for type hints,
    docstrings, error handling, `print()`, mutable defaults, and layer separation.

1.4 TOP BLOCKERS & PRODUCTION READINESS VERDICT
-----------------------------------------------
VERDICT: NOT READY FOR PRODUCTION DEPLOYMENT WITHOUT REMEDIATION.

While core architectural foundations (Django 5.1.15, Fernet secret encryption
scaffolding, parameterized ORM/SQL usage, `PromptBuilder` untrusted-data framing,
`pms.services.create_tree` atomicity, and verified removal of `InquiryCreateAPIView`
and `InquirySubmissionAdmin`) are strong, the codebase has 4 Critical security/
functional defects and 12 High defects that block production release:

  1. Security blockers: Stored XSS via `related_url` (`C-01`), 10 unvalidated
     `next` Open Redirects (`C-02`), public-visitor notification/channel spam
     via `WebsiteAssistant -> create_global_reminder` (`C-03`), unthrottled +
     spoofable `BlogPostEngagementAPIView` (`H-07`), and weak SHA-256 fallback
     for malformed `FIELD_ENCRYPTION_KEY` in production (`H-10`).
  2. Functional & RBAC blockers: Broken `/` Hub Portal (`C-04`), unauthenticated-
     tier RBAC bypass on `core` reminders (`H-01`), `VIEWER` access to
     `/meta/approvals/` (`H-02`) + double-send race (`H-03`), CRM M2M `services`
     silent data loss (`H-04`), PMS task hours multiplied by member count
     (`H-05`), and Floating AI Chat freezing on tool approvals (`H-06`).
  3. Test & CI blockers: `../.venv/bin/python -m pytest` fails immediately and
     full-repo discovery crashes on `core/test_meta_ai.py` (`H-12`).
